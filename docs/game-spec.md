# エクストリームオセロ（仮称）— ゲーム仕様書

最終更新: 2026-09-16

本書は開発用の仕様書である。**要件（固定方針）**と**試作用の仮設定（検証用・変更しうる）**を区別して記載する。

---

## 1. 要件（ユーザー指定・方針）

### 1.1 最終的に作りたいゲーム

- 10×10マスのリアルタイム型リバーシ。
- 通常の交互手番ではなく、自分の待ち時間が終われば着手できる。
- 中央4×4マスに石を配置して開始する。
- 対戦相手はCPU。
- CPUには20段階のレベルがあり、勝つと次のレベルが解放される。
- 最終的には、このゲーム専用の強化学習で育てたCPUを組み込む。

### 1.2 今回の試作範囲

- ブラウザで動く1人用ゲーム。
- PCとスマートフォンの両方で操作できる。
- 簡易CPUと最後まで対戦できるところまで作る。
- 20段階のレベル、進行保存、強化学習は今回実装しない。
- ただし、簡易CPUを学習済みCPUへ差し替えられる構造にする。
- 外部AI API、バックエンド、ログイン、オンライン対戦は不要。
- GitHub Pages に静的サイトとして公開し、友達は URL をブラウザで開いて遊ぶ。

### 1.3 技術構成

- React
- TypeScript（`strict` を有効化）
- Vite
- 通常のCSS
- Vitestによる自動テスト
- npmで依存関係を管理
- 不要なライブラリは追加しない
- 公開は GitHub Pages（静的ファイルのみ。サーバー処理はしない）

### 1.4 設計方針

- 盤面ルール、時間処理、CPU、画面表示を分離する。
- ゲームの正しい状態を複数箇所で重複管理しない。
- ルール部分は React、DOM、実時計に依存させない。
- 時刻と乱数をテストから制御できるようにする。
- CPUには盤面、双方の待ち時間、残り試合時間などの公開情報だけを渡す。
- CPUの窓口は「状態を受け取り、着手または待機を返す」形にする。
- 手番が来る前に読み進めたいCPUのために、**着手を返さない下読みの呼び出しを任意で持てる**。
  下読みは公開情報だけを受け取り、ゲームの状態を変えない。使わないCPUは実装しなくてよい。
- 過度な抽象化はせず、最小限の構造にする。

## 2. 試作用の仮設定（初期仕様・検証用）

以下は最終確定ではなく、遊んで検証するための初期仕様である。変更する場合は仕様書と進捗を更新してから実装する。

### 2.1 盤面

- 10×10マス。
- 行と列は内部では 0〜9 で管理。
- 中央の行 3〜6、列 3〜6 に 16 枚配置する。
- 中央4×4の左上を黒として、市松模様に配置する。
- 黒8枚、白8枚で開始。
- プレイヤーは黒、CPUは白。

### 2.2 石の置き方

- 縦、横、斜めの8方向で、相手の石を自分の石で挟むと反転。
- 少なくとも1枚返せる空きマスにだけ置ける。
- 通常の交互手番制にはしない。
- 相手が置いていなくても、自分の待ち時間が終了していれば再び置ける。

### 2.3 待ち時間

- 自分の着手成功から次の着手まで、700 ミリ秒（0.7 秒）。試遊により最適と判断した値で固定する。
- 開始画面では待ち時間を選べない。プレイヤーとCPUに同じ値を適用する。
- プレイヤーとCPUで別々に管理する。
- 回復は1回分まで。長く待っても連続着手の権利は貯まらない。
- 不正な着手では盤面も待ち時間も変えない。
- 待ち時間中の入力は捨てる。予約着手にはしない。
- 開始カウントダウン終了時、双方とも着手できる状態にする。

### 2.3.1 開始カウントダウン・CPU判断待ち（試作）

- 開始前に 3・2・1 のカウントダウン（合計 3000 ミリ秒のゲーム内時間）を行う。
- カウントダウン中は試合時間とCPUを進めない。
- CPUは着手可能かつ合法手がある状態から、500 ミリ秒の判断待ちのあと着手する。
- 判断待ちはクールタイム（700ms）とは別設定である。
- 判断待ち中に盤面が変わったら、500 ミリ秒待ち直す。
- 判断待ちもゲーム内時間で管理し、一時停止中は進めない。

### 2.3.2 無操作時の自動着手（試作）

- プレイヤー（黒）と CPU（白）は、それぞれ独立した無操作タイマーを持つ。
- その側が着手可能（待ち時間 0 かつ合法手がある）なのに、ゲーム内時間で 3000 ミリ秒以上置かなかった場合、合法手からランダムに 1 手を着手する。
- お互いが待ち続ける戦略を封じるため、双方に同じ制限を掛ける。
- カウントダウン中・一時停止中・終了後は計測も自動着手もしない。
- 待ち時間中、および合法手がない間は計測しない。再び着手可能になったら 3000 ミリ秒から数え直す。
- 相手の着手で盤面が変わっても、自分が着手可能なままなら自分の計測はリセットしない。
- 同じステップにその側の通常の着手要求がある場合は、そちらを優先し自動着手しない（プレイヤー入力、CPU判断待ち後の着手）。
- CPU の判断待ち（500ms）とは別である。判断で待機を選び続けても、無操作 3000 ミリ秒で強制着手する。
- 画面対戦と、遺伝的アルゴリズムの画面なし対戦の両方に含める（待ち合いが学習でも得にならないようにする）。
- PPO 経路の学習用環境には、今回は含めない。
- 試作UIでは、スコアカードの行動ゲージ（0.7秒）の下に、無操作自動着手までの 3000 ミリ秒を別色のゲージで示す。残りが減るほど満ちる（行動ゲージと同じ向き）。計測していない間は空。

### 2.3.3 画面なし自動対戦（Phase 4）

- Node 上で React / DOM なしに、同じ `stepMatch` ルールで対戦できる。
- カウントダウンは省略してよいが、開始盤面・ゲージはカウントダウン終了直後と一致させる。
- 学習用の観測・行動・マスク・報酬は `docs/training-environment.md` を正とする。
- 同時着手の優先側はプレイヤー向け UI に出していないため、学習用観測にも含めない。

### 2.4 時間と同時着手

- ゲーム内の時間は 50 ミリ秒単位の固定ステップで進める。
- 同じステップに入った双方の着手要求は、同時着手として扱う。
- 1人につき1ステップで受け付ける要求は最初の1件まで。
- 同時着手の最初の優先側は、試合の乱数シードから決める。
- 同時着手が発生するたびに、次回の優先側を交代する。
- 片方だけが要求した場合、優先側は交代しない。
- 先の着手を確定した後、更新後の盤面で後の着手を再判定する。
- 後の着手が不正になったら不成立にし、待ち時間は消費しない。
- CPUは、このステップで未確定のプレイヤー入力を見て判断してはいけない。
- 盤面更新と反転アニメーションは分離する。

### 2.5 置ける場所がない場合

- そのプレイヤーだけ待機する。
- 相手の着手で合法手が生まれたら復帰する。
- 「合法手がない」と「待ち時間が残っている」を区別する。

### 2.6 終了条件

次のいずれかで終了する。

- 盤面が埋まった。
- 盤面上で双方の合法手がなくなった。
- 試合時間 180 秒に達した。

終了時の扱い:

- 終了時の石数で勝敗を決める。
- 同数は引き分け。
- 終了後の入力やCPU処理は盤面に反映しない。
- 時間切れと同時刻以降の着手は受け付けない。

### 2.7 一時停止

- プレイヤー、CPU、待ち時間、試合時間をまとめて止める。
- 別タブへの移動などでページが非表示になったら自動停止する。
- 戻ってきても勝手に再開せず、再開ボタンを表示する。
- 再開時に停止中の時間をまとめて進めない。
- 停止前の未処理入力を、再開直後に実行しない。
- 一時停止中に「中断」を選べる。対戦中（停止していない状態）では中断できない。
- 中断すると試合を破棄し、開始画面に戻る。結果画面は出さず、勝敗にも含めない。
- CPU種類の設定は開始画面に残す。
- 中断時の未処理入力は捨てる。

### 2.8 サウンド（試作）

方針（このゲーム向けの一体設計）:

- テーマは「電脳世界のリアルタイム対戦」。刺さる高音より、空間感のある柔らかい合成音を優先する。
- BGMは画面の役割を支える。SEは操作の手触り（ASMR寄りの低〜中域）を担う。BGMよりSEが聞き取りやすい音量関係にする。
- 音声ファイルや追加ライブラリは使わない。ルール層・CPU・試合状態機械には載せない。

BGM:

- 選択画面: ゆったりした電脳ロビー（中域が聞こえる。待機の安心感）。
- 対戦画面（カウントダウン含む）: 鼓動のある緊張感。うるさすぎない駆動リズム。
- 結果・勝ち: 少し明るく上がる余韻。
- 結果・負け: ゆっくり下がる余韻。
- 結果・引き分け: どちらにも寄らない浮遊感。

SE / 再生制御:

- 石が盤に乗ったとき（プレイヤー・CPU・自動着手）に着手SE。不正なクリックでは鳴らさない。黒と白で少し音を分ける。
- 開始・CPU選択・一時停止・再開・中断・再戦・開始画面に戻る・BGM切替などのボタンに短いUIのSE。
- 最初の操作（タップ / クリック / キー）のあとから再生開始。
- 一時停止中とページ非表示中はBGMを止める。再開したら同じ曲を続ける。
- 初期状態はBGMオン（ミュートしない）。ミュート切替を画面上に置く。永続保存はしない。ミュート中はBGMとSEの両方を止める。
- 反転専用の効果音は今回の対象外。

### 2.9 CPUの種類（試作）

開始画面で選べる CPU は次の並び。既定は先頭のベータ。

1. **ベータ** — 現行の正式版。23時のアルファに全滅の余裕を足し、直接対戦で明確に勝ち越した設定。
2. **アルファ** — 2026-09-15 23時の正式版。着手可能数 1.5 倍。比較用に残す。設定は上書きしない。
3. **戦略AI（最強クラス）** — 開発中の現行版。調整のたびに中身が動くので、比較の基準として残す。
4. **アン（時間読みAI）** — 時間イベント型 MCTS。手番ではなく「次の意思決定イベント」を探索し、双方のクールタイムと判断待ちを状態に持つ。実測と設定は `docs/ai-experiments.md` に残す。
5. GA育成（世代ごと） — 遺伝的アルゴリズムで育てた評価CPU。
6. ランダム型 / 即時反転数優先型 — 動作確認用の簡易CPU。

名前付き個体（アルファ、ベータ、以降はガンマ…）の決まりごと:

- 中身は戦略AIで、強さを実測で裏取りできた設定に固定する。設定値と実測は `docs/strategy-ai.md` に残す。
- 過去の名前付き個体の設定は上書きしない。強くなった版には新しい名前を付ける。
- 新しい名前をゲームに載せる条件は、**過去の名前付き個体すべて**との直接対戦で、それぞれに明確に勝ち越したと証明すること。
- 明確に勝ち越し = 黒白交互・開幕ランダム・60戦以上で、得点率の Wilson 95% 下限が 50% を超える。
- 比較相手は名前付き個体だけ。戦略AI（開発中）、アン、GA、簡易CPUはこの系列の昇格条件に含めない。
- 既定の対戦相手は、条件を満たした最新の名前付き個体。

アンの決まりごと:

- 公開情報だけを見る。相手の判断待ちと無操作タイマーは公開されないので、未計測として扱う。
- 自分の判断待ち（500ms）は読みに入れる。盤面が変われば待ちが戻るため、相手の着手直後は即応できない。
- 相手（人間）の判断待ちは 0 として読む。ゲージが回復した瞬間に打てる前提にする。
- 探索は盤面が変わったときの 1 回だけ。判断待ちの間の下読みで済ませ、結果は次の盤面変化まで使い回す。
- 同じ局面からは必ず同じ手を返す（乱数は盤面から決める）。下読みの回数で手が変わらない。

名前付き個体と戦略AIは同じ探索を使う。評価の重みは個体ごとに固定する。以下は探索の決まりごととして両方に適用する。

戦略AIの決まりごと:

- 公開情報（盤面・双方の待ち時間・試合内の経過時間・残り試合時間）だけを見る。1.4 の窓口を変えない。
- 打ち切りは実時計ではなく**展開ノード数**で行う。同じ試合の同じ進行と乱数からは必ず同じ手を返す。
- 相手の着手間隔は決め打ちせず、**その試合の観測から推定**して読みに使う。観測は公開情報だけから行い、試合をまたいで持ち越さない。
- 相手の速さは**読みの日程にだけ使い、評価は変えない**。速さに応じて
  「石が尽きる危険」を早めに嫌う案を試したが、弱い相手には効く一方で
  強い相手には負け越したので入れていない（`docs/strategy-ai.md`）。
- 全滅（2.7 の 0 枚敗け）の危険は、ベータと戦略AI（開発中）では**石数ではなく実際の反転で測る**。相手の 1 手で
  返される自分の石の枚数を数え、全部返る形を別格に嫌う。石が少ないこと自体は
  危険ではない（確定石が 1 つあれば返らない）ので、石数だけでは代理にならない。
  アルファ（23時固定）はこの項を持たない。
- 自発的な待機はしない。2.3.2 の無操作 3 秒でランダム着手にされるため、打てるときは必ず自分で選んだ手を置く。
- 探索は 2.4 の 50ms ステップ内で同期実行する。1 手あたりの計算量は、プレイヤーの入力遅延にならない範囲に収める。
- 手番が来る前のステップで読み進める（下読み）ことは 1.4 の窓口として許すが、
  **既定では使わない**。実装はあるものの、対戦では下読みなしに負け越したため切ってある（`docs/strategy-ai.md`）。
  使う場合も、1 ステップの計算量は着手時より小さくし、読んだ結果は盤面が変わった時点で捨てる。
  下読みは着手を返さず、2.3.2 の判断待ち 500ms を早める用途には使わない。

詳細と計測結果: `docs/strategy-ai.md`。

### 2.10 ライフ（試作）

画面対戦のプレイヤー用。盤面ルール・CPU・画面なし対戦・学習には載せない。

- 上限は 5。初期状態は 5。
- プレイヤー（黒）が負けると 1 つ減る。中断でも 1 つ減る。勝ち・引き分けでは減らさない。
- 残りが 0 のあいだは、開始と再戦ができない。
- 端末のローカル暦日が変わると、残りを 5 に戻す。1 日 1 個ずつではない。
- 残りと、最後に見た暦日は端末の `localStorage` に残す。端末をまたいでは共有しない。
- 時刻はテストから差し替えられるようにする。ルール核の試合時間とは別である。

### 2.11 公開（試作）

- GitHub リポジトリにソースを置き、GitHub Pages でゲーム本体を配信する。
- 公開 URL をブラウザで開けば、インストールなしで遊べる。
- オンライン対戦にはしない。各自が自分のブラウザで CPU と戦う。
- ライフは端末ごとの `localStorage` のまま。友達の端末とは共有しない。

## 3. 用語メモ

| 用語 | 意味 |
|------|------|
| 待ち時間 | 着手成功後に次の着手が可能になるまでのクールダウン |
| 同時着手 | 同一の 50ms ステップ内に双方の着手要求が入った状態 |
| 公開情報 | CPUに渡してよい情報（盤面・双方待ち時間・残り試合時間など） |
| 優先側 | 同時着手時に先に確定する側。発生のたび交代 |

## 4. 今回実装しないもの（明示）

- 強化学習モデルの学習・組み込み本体（画面なし環境と差し替え口までは Phase 4）
- 外部AI API / バックエンド / ログイン / オンライン対戦
- 20段階のCPUレベルと解放進行
- レベル解放などの進行状況の永続保存（ライフの端末保存は 2.10）
- Python / GPU 学習パイプライン
